# 项目概览与系统架构

## 1. 项目目标

Byt 测评系统是一个面向小红书内容运营的半自动化测评后台。系统目标是把一次测评内容从“产品输入”推进到“笔记草稿、发布记录、数据复盘”的闭环。

核心工作流：

```text
选品 / 体验记录
  -> 上传产品图片、名称、价格、购买渠道或直观感受
  -> Agent 生成标题、正文、标签、封面文案、图片建议
  -> 存储为一篇草稿帖子
  -> 用户手动发布到小红书
  -> 回到系统标记已发布
  -> 7 天后录入浏览、点赞、收藏、评论、涨粉
  -> 系统计算指标并生成复盘
  -> 为下一期选题提供建议
```

## 2. MVP 范围

当前实现覆盖：

- 产品卡片式录入。
- 产品图片上传。
- 图片处理风格：系统默认 / 自定义自然语言风格。
- 文案生成风格：系统默认 / 自定义自然语言风格。
- 文案生成，包括标题候选、正文、封面文案、标签、评论引导、整体推荐程度。
- 草稿、已发表、已分析三种帖子状态。
- 标记已发布后自动创建数据录入提醒。
- 数据录入与指标计算。
- 基于指标生成复盘分析。
- 首页概览和内容管理。

当前未完成但已预留：

- 真实 OpenAI Responses API 调用。
- 真实图片生成/编辑服务。
- 阿里云 OSS SDK 上传。
- 用户登录和权限。
- Alembic 数据库迁移。

## 4. 业务状态流转

帖子状态：

```text
draft -> published -> analyzed
```

状态含义：

| 状态 | 含义 | 触发方式 |
| --- | --- | --- |
| `draft` | 草稿，尚未发布 | 创建帖子默认状态 |
| `published` | 用户已在小红书手动发布 | 调用 `POST /api/posts/{post_id}/mark-published` |
| `analyzed` | 已录入数据并生成复盘 | 录入指标时 `analyze=true` 或调用分析接口 |
